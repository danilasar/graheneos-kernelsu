# Обновление и откат без потери данных

Текущий комплект: Pixel 8 shiba, GrapheneOS **2026100601**, KSU **v3.4.1/33333**, SPL **2026-10-05**. Полная процедура установки: [INSTALL.md](INSTALL.md).

## OTA GrapheneOS

1. Сделай резервную копию важных данных. Запиши сборку/fingerprint, слот, kernel release, bootloader state; сохрани штатные образы **текущей** ОС и их SHA256.
2. Перед OTA восстанови только изменённые загрузочные разделы активного слота штатными образами этой же версии. В финальной установке 2026100601 на обоих телефонах менялся только `boot_a`. Нельзя переносить историческую команду восстановления `init_boot_b` на текущий A.
3. Для build 2026100601 и активного A, если boot_a действительно изменён:

```sh
adb -s "$SERIAL" reboot bootloader
fastboot -s "$SERIAL" getvar current-slot
# Продолжить только при current-slot: a и заранее проверенной ОС 2026100601:
fastboot -s "$SERIAL" flash boot_a artifacts/2026100601/stock-boot.img
fastboot -s "$SERIAL" reboot
```

Нетронутый init_boot не перепрошивать. Для другого слота/выпуска подставляй только проверенные matching образы и разделы.

4. Дождись штатной загрузки, установи OTA через GrapheneOS System Updater. При ошибке остановись и сохрани журнал; никаких `flash-all.sh`, `-w`, reset или relock.
5. После OTA запиши новую ОС, SPL и активный слот. KSU может исчезнуть: OTA загружает новое штатное ядро из другого слота.
6. Получи точные новые источники и stock boot из подписанного официального архива, перенеси патчи вручную, пересобери. Не прошивай нынешний KSU образ на новую ОС.
7. **Заново извлеки и проверь сертификат модуля из stock kernel новой версии.** Ни совпадение имени CN, ни kernel release не гарантируют прежний сертификат. Проверку подписей модулей не отключать.
8. Установи совместимый полноценный APK, временно загрузи кандидат через fastboot boot, проверь фактическую загрузку KSU, текущий dmesg, boot reason/uptime, Manager root, модули и приложения. Только затем, с разрешения владельца, записывай активный boot.

## Обновление KSU и Manager

KSU встроен: смена версии драйвера требует нового ядра, не только APK. Обновление APK отдельно возможно, если package и сертификат совпадают с ожиданиями ядра и UAPI совместим.

Текущая identity: `com.rifsxd.ksunext.prctl341`, certificate SHA256 `b4eb1c14210fff0e1d8102e0f54a9cd1dfd674050dc3a520ff88dc8c048b0da3`, размер DER `744` / `0x2e8`. Новый ключ или package требует согласованной пересборки ядра и APK. Ключ подписи не публикуется.

Не устанавливай старый неполный APK: исправленный — `artifacts/2026100601/Manager-prctl341-with-ksud.apk`. Проверяй наличие libksud.so и его PRCTL-сборку. Проверка на телефоне с уже работающим root может скрыть отсутствующие компоненты, поэтому нужен тест чистой установки.

Разрешения приложений обычно сохраняются после OTA, но их надо проверить. Root Manager, shell UID2000 и root Neo Backup — разные права. Не выдавай широкие capabilities всем приложениям.

## Неудачная временная загрузка

`fastboot boot` не записывает раздел. При отказе и обычной перезагрузке возвращается штатный/предыдущий образ из boot. Если телефон доступен после теста, это ещё не значит, что кандидат успешно загрузился: проверь watchdog reason, uptime, KSU driver и текущий dmesg. LAST KMSG относится к предыдущему запуску и может показывать неудачный KSU boot.

Не повторяй blind flash/scan. Сначала объясни отказ по журналам: signature rejection, ABI/vermagic, hooks, package verifier, fd transport и userspace проверяются отдельно.

## Откат постоянной установки

Из bootloader проверь слот. Восстанови только изменённый boot штатным образом **установленной сейчас версии ОС**. Для 2026100601 stock boot в artifacts/2026100601; для другой версии эти файлы запрещены. Не переключайся на старый слот как универсальный откат: возможны несовместимость системных разделов и защита от отката.
